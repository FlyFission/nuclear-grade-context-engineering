# Control Ladder: skill versus prompting

Pool: **negative** · Scoring: **rubric** (independent binary checks)

Generated by `scripts/analyze_ladder.py`. Do not hand-edit — rerun it.

## What this measures

The `skill-benchmark-pilot` in this repo compares a loaded skill against a bare
prompt with nothing appended, which measures skill-versus-nothing. This ladder
adds the intermediate arms needed to measure skill-versus-*prompting*. Every arm
uses an identical model, tool allowlist, budget cap, isolation flags, scenario,
and grading criterion; the only thing that varies is the text appended to the
system prompt.

| Arm | Appended to system prompt |
|---|---|
| `C0_bare` | bare prompt (nothing appended) |
| `C1_generic_nudge` | generic skill-agnostic reviewer nudge |
| `C3_compressed` | skill compressed to <=5 imperative bullets |
| `C4_full_skill` | full SKILL.md body |

The C1 control text, identical for all skills and containing no vocabulary
from any of them:

> Before you answer, think like a careful senior reviewer accountable for the outcome. Identify what is missing, unstated, or assumed; what could go wrong and who would be affected; who needs to approve, be informed, or own the risk; and what evidence would actually back any claim you make. State the gaps, risks, and non-obvious consequences explicitly rather than leaving them implicit, and say plainly when something should not proceed as-is. Be specific and concrete rather than general.

## Instrument validity

A scenario where every arm scores 1.00 (ceiling) or every arm scores 0.00
(floor) cannot express a difference between arms. Equality there is a
property of the scenario, not a finding about the skills. Every skill is
classified before any pooled statistic is computed, and the classification is
published so a reader can see which cells carry information. They are NOT
dropped from the primary test -- see Primary result for why keeping them is
the conservative choice.

- Informative: **26/29**
- Ceiling (all arms >= 0.95): **3**
- Floor (all arms <= 0.05): **0**
- Rubric checks met: **1370/1740** (79%) across 348 gradings

Ceiling skills — these cells cannot express a difference, so they carry no information about the skill either way. They are still INCLUDED in the primary test (see below for why that is the conservative choice): `breaking-down-the-work`, `checking-release-readiness`, `creating-change-records`

## Primary result

Pre-specified hypothesis: across the 29-skill pool, the full skill (C4) does NOT score below the generic prompting control (C1) on paired per-skill proportionality scores -- these scenarios sit inside each skill's own declared exclusion, so a LOWER C4 is the cost finding and a null is the good outcome. Tested once.

This figure spans **all** skills in the pool, ceilings and floors included. They are not dropped: a cell that cannot express a difference contributes a zero and pulls the mean toward zero, so including it is the conservative choice. Filtering on the validity gate would raise the effect and would be a post-hoc selection that depends on observing the treatment arm.

- Mean paired difference: **+0.030** (score scale 0–1; YES=1, PARTIAL=0.5, NO=0)
- Skills where C4 > C1: **10** · C4 < C1: **6** · tied: **13**
- Two-sided exact sign test: **p = 0.4545**
- Two-sided paired permutation test (100,000 resamples, seed 20260726): **p = 0.3438**

Restricted to the 26 informative skills (ceilings and floors
removed): mean **+0.033**, 10 better / 6 worse / 10 tied, sign p = 0.4545, permutation p = 0.3442.

## Per-skill scores

Mean score over 3 trials, 0–1, with a 95% percentile bootstrap interval on
C4−C1 (10,000 resamples of trials within each arm, seed fixed).

**No per-skill helps/hurts verdict is issued.** A bootstrap over three trials
is itself unreliable: when all three trials happen to agree, it reports an
artificially tight interval because it can only resample the values it saw.
So an interval excluding zero here is a weak signal, not a verdict, and a
wide one is a reliable statement that nothing can be concluded.
An earlier version of this report classified skills against a hardcoded
threshold and produced two claims the data did not support — four skills
called harmful on one-check flips, and a proposal to delete ~14,000 words of
skill text. Both were retracted. Intervals replace the threshold so the same
over-reading is not available.

The pooled tests above are unaffected: they aggregate every skill and carry
their own permutation p-values.

## Limitations

- **One subject model** (`claude-sonnet-5`), one scenario per skill, 3 trials per
  cell. Everything here is Sonnet-specific until replicated.
- **Criteria are less contaminated here, but not independent.** This pool's
  scenarios and criteria were generated per scenario by an author shown only the
  skill's name and frontmatter description — never the SKILL.md body — so they
  cannot simply restate the skill's checklist the way the reused pilot criteria
  can. They are still not external: one model wrote both the scenario and its
  criterion, and the description still describes the skill.
- **Forced-load proportionality, not over-firing.** Every scenario sits inside
  the territory the skill's own frontmatter excludes, and the skill is then
  injected anyway. That measures whether its body still permits a proportionate
  answer -- NOT whether the library would have selected it. Real over-firing
  needs whole-catalog routing, which is unmeasured.
- **Known confound.** Some scenarios ask the model to edit project files while
  the isolated work directory is empty and tools are read-only, so the response
  asks clarifying questions and the rubric partly scores a missing fixture as
  disproportionate. Treat a null here as UNSUPPORTED, not as evidence of no cost.
- **29 of the 29 skills on disk have a scenario.** `verifying-final-artifacts`
  has no eval coverage at all; `reviewing-code-quality` is covered by the separate
  3-task pilot rather than this pool.
- **The C1 text is one specific paragraph.** A different generic control would
  move these numbers. It was written to be strong on purpose; a weak control
  would inflate every skill's measured effect.
